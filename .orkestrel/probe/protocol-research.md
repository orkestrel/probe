### What the specification itself says

The 2026-07-28 revision (modelcontextprotocol.io/specification/2026-07-28/basic/versioning) replaces the `initialize` handshake with per-request `_meta.protocolVersion` fields and a required `server/discover` RPC that a server **MUST** implement and a client **MAY** call up front. It formally names the earlier dated-`initialize` revisions (`2025-11-25` and earlier) "legacy" and the per-request style "modern," and defines a `Dual-era` implementation as one supporting both. Its compatibility matrix states that a modern client against a legacy server "fails" unless it is dual-era and probes first; that a legacy client against a modern-only server "fails" with no fall-forward mechanism; and that dual-era-to-legacy and dual-era-to-modern both "work" through the probe/fallback path. Prior dated revisions (`2025-06-18`, `2025-11-25`) carry no discovery RPC or per-request versioning at all — they are handshake-scoped for the life of the stdio process, and a server on those revisions has no way to advertise multi-version support beyond the single `protocolVersion` it returns from `initialize`.

## Distribution a stdio server must expect in 2026-08, and coverage

Verified: Claude Code (dual-era, probes `server/discover`, changelog dated through 2026-08-20) and the Python SDK v2 client (dual-era by default, released 2026-07-28) are already modern-capable and will negotiate whichever revision a server offers, `2026-07-28` included. Verified: the TypeScript SDK client remains legacy-only unless the calling application explicitly opts into `auto` or `pin` mode, so any TypeScript-built client that has not made that opt-in choice — a fact this research cannot check per application — still sends a `2025`-era `initialize` regardless of what the server supports. Verified for a point in time (around April 2026, unconfirmed for August) but not for the present: Claude Desktop and VS Code Copilot Chat send `2025-11-25`. Unresolved from public sources: Cursor's and Windsurf's default revisions and whether either has adopted `server/discover`.

Given that mix, a stdio server published in 2026-08 must expect legacy `2025-06-18` or `2025-11-25` `initialize` requests from a meaningful share of real clients — including, on present evidence, VS Code Copilot Chat and any TypeScript-SDK-built client that has not opted into `auto`/`pin` negotiation — alongside modern `server/discover` probes from Claude Code and Python-SDK-built clients, with Claude Desktop's and Cursor's and Windsurf's current behavior not established.

A server that implements `server/discover` per the 2026-07-28 spec and additionally answers `initialize` for `2025-06-18` and `2025-11-25` satisfies every verified client behavior in this table, including the unconfirmed clients, because the spec requires exactly that dual-era shape for interoperability with legacy `initialize`-only clients and the modern discovery-probing ones both.
